# C0 P2P 설계 검증 보고서

2026-10-17 · 브랜치 `sangwookpark/ib-p2p-c0` · 시작 HEAD `c10a7ea` · 작업 T6(워커 c0)

## 변경

- 새 문서 `docs/superpowers/specs/2026-10-17-p2p-c0-design.md` 하나를 추가했다. 제품 코드, 테스트, 설정은 바꾸지 않았다. `dev/` 실험 디렉터리도 만들지 않았다. 이번 결론에 실험이 필요한 항목은 C1으로 넘겼다(설계 문서 §9.4).
- 문서는 다음을 다룬다.
  - 위협 모델: 행위자별 대응과 남는 위험, 그리고 보장하지 않는 것(§2).
  - 기기 신원: 사용자 키 없이 기기 키 세 쌍을 두고, incarnation으로 복제를 감지한다(§3.1~3.2).
  - 멤버십: 권한 기기 한 대가 서명하는 해시 사슬 로그. 분기를 감지하고 신선함을 지킨다(§3.3).
  - 쓰기 권한 검증 다섯 단계(§3.4).
  - 키 교체 3단계와 seal-at-send. 오프라인 편집을 잃지 않는다(§3.5).
  - 제거 cutoff와 격리(§3.6). 기기 추가, 승계, 복구 코드(§3.7).
  - 봉투 형식, 그리고 연속 카운터로 누락을 감지하는 방법(§4.1~4.2).
  - 스냅샷: 합칠 수 있는 체크포인트로 다루고, 로컬에서 포함을 검증한 뒤에만 업데이트를 지운다(§4.3~4.5).
  - 암호화된 registry 문서, 허브 신호 다섯 개와의 대응 표, 충돌 규칙(§5).
  - 삭제·복구 계약, bootstrap 완료 기준, 제거된 기기의 처리, ACK와 보존 상태, 용량 초기값(§6).
  - 기술 평가와 권고, 연결 계층 설정(§7).
  - 지금 코드와의 접점을 파일:줄로 정리하고, 다시 돌릴 회귀 테스트를 골랐다(§8).
  - C1 작업 14개(C1-0~C1-13), 측정, 남은 추측(§9). 참고 자료 링크와 확인일(§10).
- **권고:** Iroh 1.3을 연결 계층으로만 쓰고, 봉투·멤버십·registry·스냅샷은 직접 구현한다.
  - NextGraph는 1차 기반으로 쓰지 않는다. 브로커가 필수이고, 브로커 없는 LAN 동작이 문서에서 확인되지 않으며, alpha다.
  - PRD 후보 밖의 p2panda(Iroh 기반, MIT/Apache-2.0, 0.7.1)는 부품 후보로 관찰한다.
- **조사 중 PRD와 다르게 확인한 사실** (PRD 수정은 하지 않았다)
  - 노트 확장자 목록은 세 개가 아니라 네 개다(`R/vault.rs`, `D/lib/formats.ts`, `D/lib/sync/registry.ts`, `D/lib/sync/inbound.ts`). `formatsLockstep.test.ts`가 넷을 함께 검사한다. `CLAUDE.md`도 "세 목록"으로 적고 있다.
  - PRD §13의 FOSDEM 링크는 확인일에 404였다. 2026 archive 주소를 설계 문서 §10에 적었다.
  - Iroh 공식 문서는 n0 공개 중계를 "개발과 테스트용"으로 설명한다. C2 전에 중계 운영 결정이 필요하다.
  - 허브의 HocuspocusProvider 수신은 `ORIGIN_REMOTE`가 아니라 provider 객체를 origin으로 쓴다. `ORIGIN_REMOTE`는 지금 `applyRemote`에서만 쓰인다.

## 미검증

- 설계의 실제 동작 전부: Iroh mDNS 순수 LAN 연결, 봉투·키 교체·스냅샷 병합. C1에서 검증한다.
- §8 표 가운데 다시 대조하지 않은 줄 번호. 조사 단계에서 파일을 읽어 정리했지만 하나하나 재확인하지는 않았다.
- 외부 사실 가운데 확인하지 못한 것
  - NextGraph에 브로커 없는 직접 동기화나 mDNS가 있는지.
  - NextGraph 앱이 Tauri 기반인지.
  - Iroh 연결 키가 Ed25519라는 공식 문서 문장.
  - Rust에서 직접 쓰는 mDNS에 `NSBonjourServices` 선언이 필요한지.
  - Ditto의 라이선스 조건.
  - BFT CRDT 논문 링크의 재확인.
- 보안 리뷰. 이 문서는 자체 설계이며 외부 감사를 받지 않았다. C2 출시 조건이다.

## 사용자 결정 필요 항목

각 항목에는 안전한 기본값을 적었다. 결정이 없으면 C1은 이 기본값으로 진행한다.

| # | 결정 | 기본값(권고) | 근거 위치 |
|---|---|---|---|
| 1 | C0 기술 선택 승인 (PRD Q1) | Iroh 1.x + 직접 구현. NextGraph 제외, p2panda 관찰 | 설계 §7.3~7.4 |
| 2 | 여러 관리자 기기가 동시에 멤버십 권한을 가질지 (Q4) | 아니오. 한 번에 권한 기기 한 대, 이양만 가능 | §3.3 |
| 3 | 구 epoch 보존 기한 (Q5) | 30일 유지. 이 설계에서는 정확성 조건이 아니라 대역폭 최적화와 격리 검토 기간에만 쓰인다 | §3.5 |
| 4 | 복구 코드의 형식과 단위, 건너뛰기 허용 | vault마다 하나, 건너뛸 수 없음, 대소문자 구분 없는 영숫자 묶음 | §3.7 |
| 5 | 복구 코드로 권한을 되찾을 때 복구 코드 재발급을 강제할지 | 강제한다 | §3.7 |
| 6 | 제거된 기기의 로컬 노트 처리 | 허브와 같이 지운다(같은 회수 상한 적용). 그 기기의 미전송 변경만 "보내지 못한 내 변경" 사본으로 남긴다 | §6.4 |
| 7 | 제거 cutoff 기준 | 권한 기기가 본 카운터. 그 뒤의 봉투는 격리하고 관리자가 검토한다(정직한 늦은 변경도 격리됨) | §3.6 |
| 8 | bootstrap 완료에 필요한 확인 출처 | 권한 기기 1대, 또는 다른 사용자의 기기 2대(D 단계 이후 저장 노드 1대도 인정) | §6.3 |
| 9 | 기본 중계: n0 공개 중계를 쓸지, 직접 운영할지 (Q3와 연결) | C1은 중계 없음(사내망 전용). C2 전에 결정. 공개 중계는 공식 문서상 개발·테스트용 | §7.5 |
| 10 | 봉투 크기 덧댐(트래픽 분석 완화) | C1에 넣지 않음. C2 보안 리뷰에서 다시 결정 | §2.4 |
| 11 | 사용자 키를 두지 않는 신원 모델 | 두지 않는다. 기기 키와 권한 기기 서명만 쓴다 | §3.1 |
| 12 | 같은 경로 충돌 시 디스크 이름 규칙 | `이름 (충돌 <doc_id 앞 6자>).md`, `doc_id`가 작은 쪽이 원래 이름 | §5.3 |
| 13 | 용량 상한 초기값 | 봉투 4 MiB, 문서 16 MiB, 스냅샷 기준 500개/1 MiB, 기기 64대 | §6.6 |
| 14 | `CLAUDE.md`의 "세 확장자 목록" 문구를 네 목록으로 고칠지 | 고친다(별도 작은 commit, 이번 작업에서는 하지 않음) | 설계 §8.5 |
